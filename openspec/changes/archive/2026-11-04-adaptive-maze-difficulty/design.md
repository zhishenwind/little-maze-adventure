# Design

## Context

当前模型仅有 size，SVG 固定方形棋盘，手机设置与装饰占用空间。动机见 proposal.md。本轮沿用 React Web 与本地离线包。

## Goals / Non-Goals

- 行列、生成、寻路、尺寸选择和难度测量保持纯 TypeScript；浏览器仅提供可用区域。
- 固定每局尺寸，响应式变化只影响比例与排列。不加入小程序依赖或新的持久化进度。

## Decisions

- 模型改为 cols/rows，格子索引为 row * cols + col；SVG 使用每格 52 单位及紧凑边缘，消除原有装饰边框挤压。
- 三档格子目标为 56、44、35 CSS 像素。使用游戏卡实际宽度和窗口可用高度（预留游戏栏、任务和方向按钮、安全区）选择不超过上限的尺寸，最低常规 4 列 4 行；极矮窗口优先保留可操作格子并允许滚动。尺寸只在创建新局时选择。
- 手机开始后进入专注布局；返回设置不改变 phase，继续当前局也不重生成。重试保持专注与当前尺寸。设置中实际尺寸以当前局为准，新局按当前窗口重新适配。
- 使用随机生长树，从随机格起建，避免左上起点总被迫经过长走廊。有限次数生成候选，按路线长度、有效岔路和错路深度与档位目标的距离评分选取。有效岔路指解路径上可进入至少两格深的非解支路，错路深度取这些支路的最长距离均值。
- 不强制每张迷宫达到硬性指标：小屏与随机树存在结构限制。通过同尺寸固定种子批量检验分布梯度，记录结果以供试玩调参。
- 头像约为格宽的 78%；起始热区至少覆盖 44 CSS 像素直径，方向按钮至少 44×44。路径仍按经过格子采样验证墙体。

## Risks / Trade-offs

- 参数不等同于儿童能力评估 → 本轮标记为第一版，后续亲子试玩调整。
- 密集档在横屏缩放后格子变小 → 保留当前局、可旋回竖屏或主动开新局，方向按钮始终可用。
- 生成多候选增加耗时 → 限制次数并测量最大常规网格生成时间。
- main 尚未包含已交付的头像和离线提交 → 本轮分支从当前已交付提交创建，保留完整现状，不重写或合并历史。

## Migration Plan

无已保存迷宫需要迁移，累计星星与静音键保持不变。生产离线包沿用现有更新提示，用户确认更新后加载新版本。
