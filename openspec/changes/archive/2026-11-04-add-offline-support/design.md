# Design

## Context

项目运行资源均在仓库内，角色和场景为 SVG 组件，没有接口、SDK 或远程字体。现有开发体验通过局域网 HTTP 5173；该地址不能注册 Service Worker，需要生产 HTTPS 或转发至本机 localhost。

## Goals / Non-Goals

**Goals:** 首次自动保存全量运行资源，缓存成功后断网重开可玩；确保下载失败不误报、版本切换不强制中断游戏，保留现有星星与偏好。

**Non-Goals:** 不预设计接口数据缓存，不接入第三方 SDK，不保存当前局进度，不配置主机证书信任或发布云服务。

## Decisions

1. 使用项目内 Vite 构建插件生成清单，交由 Workbox 预缓存。构建自动列出带内容修订的 HTML、JS、CSS、SVG、图标和应用清单，避免人工维护资源列表；使用 SHA-256 修订并将 Worker 编译为模块，避免额外的生成器依赖，不引入 CDN，也不设置运行时接口缓存。
2. 使用小型自定义 Service Worker 提供预缓存、页面回退及离线包完整性查询。只有全部构建资源可从缓存读取且页面已受控后，界面才声明离线可用；不依赖 localStorage 中的完成标记。
3. 资源与页面从预缓存加载。非构建清单资源、非 GET 请求、接口与第三方请求保持正常网络行为，不增加运行时缓存。页面回退排除 /api，未来接入接口或 SDK 时重新评审策略。
4. 新 Worker 安装完成后等待；用户点击更新才激活并刷新。后台更新失败时旧 Worker 和缓存继续工作，不清空 localStorage。激活后清理过时预缓存资源。
5. 离线状态保存在独立模块，以 React 外部 store 订阅；避免 StrictMode 重复注册。通过 Worker 消息核验缓存，发现失效时提示重新保存；首次安装失败时重试注册，已受控页面通过 Worker 只补齐清单内缺失资源；不主动清除仍可用的旧资源。
6. 开发环境关闭 Worker，避免缓存影响热更新。生产离线测试直接提供真实 dist 静态文件，覆盖断网与浏览器新页面，并模拟安装失败和等待更新。

## Risks / Trade-offs

- 浏览器可以清除或逐出缓存 → 说明必须在首次保存完成后使用；重新在线访问可检查并重新保存，不承诺永久存储。
- 局域网普通 HTTP 不能提供离线能力 → 给出真实状态，Remote-SSH 用户使用 localhost 端口转发；正式部署需 HTTPS。
- 更新刷新会重开当前局 → 仅用户主动点击时刷新，并说明星星保留、本局重新开始。
- 引入工具链开发依赖 → 锁定 Workbox 依赖版本，运行构建和真实 Worker 验证；游戏本身无远程依赖。
