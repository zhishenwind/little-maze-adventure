# Design

## Context

当前角色是封闭的 Character 联合类型；Animal 组件被选择卡、任务栏、棋盘和庆祝画面共享。所有素材原本是 SVG，新增照片需适配 SVG 场景并成为可预缓存资源。

## Goals / Non-Goals

**Goals:** 原照片主体头像在各处一致、无青蛙外观或名称残留、断网可加载，操作与通关行为不变。

**Non-Goals:** 不把真人转换为牛形象，不变更蝴蝶目标，不改写历史归档，不引入远程图片依赖。

## Decisions

1. 使用原图确定性裁切与缩放，输出 512×512 PNG；不美化或重绘人物。图片处理服务未能完成任务，最终素材直接来自原图像素，不使用生成结果。
2. 将头像放在 src/assets，通过 Vite 导入生成带哈希文件名，已有离线构建将其自动列入清单，不额外设置运行时图片缓存。
3. Animal 在 yiyi 分支中输出带圆形裁切的 SVG image，使用 useId 创建实例独立的 clipPath，所有消费位置复用同一入口。保持外层 viewBox 与尺寸契约，不影响拖拽计算。
4. 移除原青蛙绘制分支，角色 ID 使用 yiyi；Treat 的蝴蝶分支随新 ID 复用。当前没有角色持久化或外部接口，不需要旧 ID 迁移。
5. 历史归档保留当时事实；主规格、README 和当前代码更新为新角色。测试验证多处图片一致、操作通关及断网解码。

## Risks / Trade-offs

- 照片比矢量图大 → 仅保存 512px 裁切版，不将原图纳入仓库；沿用版本化预缓存。
- 多个 SVG 头像实例可能发生裁切 ID 冲突 → 每个实例使用独立 ID，并检查页面各展示位置。
- 已缓存旧版本的浏览器仍显示旧角色 → 按既有版本机制提示更新，用户主动更新后看到新版。
