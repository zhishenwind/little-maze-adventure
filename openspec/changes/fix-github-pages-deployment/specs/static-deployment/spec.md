## Purpose

让迷宫游戏能够通过 GitHub Pages 的仓库子目录稳定发布，为用户提供可打开、资源完整且可离线保存的生产页面，并通过发布前验证避免将开发源码或错误的根路径地址暴露为游戏入口。

## ADDED Requirements

### Requirement: 发布构建后的游戏资源

项目 SHALL 将通过类型、规格、算法和浏览器检查的生产构建产物发布到 GitHub Pages，不直接发布包含 TypeScript 开发入口的源码目录；主分支代码更新与手动触发均可执行发布流程。

#### Scenario: 主分支发布成功

- **WHEN** 主分支更新且自动检查与生产构建成功
- **THEN** 发布构建后的 HTML、JavaScript、样式、照片、应用清单和离线 Worker，首页展示游戏

#### Scenario: 检查未通过

- **WHEN** 任一必要检查或生产构建失败
- **THEN** 不部署失败产物，已发布版本不被该失败任务覆盖

### Requirement: 根路径与仓库子目录部署

项目 SHALL 保留默认根路径构建，并提供 `/little-maze-adventure/` 专用构建；子目录中的脚本、样式、图标和照片须正确加载，应用清单的启动地址与作用域须解析为当前应用目录。

#### Scenario: 访问仓库站点

- **WHEN** 用户打开 `/little-maze-adventure/`
- **THEN** 页面显示迷宫和全部选择，资源请求不错误指向站点根目录的 `/src/` 或 `/assets/`

#### Scenario: 在手机完成冒险

- **WHEN** 用户通过仓库站点在手机拖动角色、松手后续走并到达终点
- **THEN** 角色不能穿墙，能够显示通关庆祝，页面不存在白屏或缺失照片
